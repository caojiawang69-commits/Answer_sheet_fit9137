怎么找到发往 Web 的帧 4.1 前置

  1. 过滤栏输入 ip.dst == 61.143.77.112，回车。剩下的每一行都是发往 Web 的。
  2. 随便右键一行 → Follow → TCP Stream。
  3. 弹出对话内容窗口，点右下角 Close。
  4. 过滤栏自动变成 tcp.stream eq 1，列表里只剩这一条连接。

随便选哪一行都行：发往 Web 的帧都属于同一条连接（Apollo 53139 → Web 80）。

我的列表和图不一样，帧号跳着走 排序

现象：只看到 143、145、146……少了 144 [SYN, ACK]。

原因是点过 Source 列的标题，列表按 Source 排序了：Apollo 发的帧排在前面，Web 回的帧都被排到下面。

只要帧号不是从小到大，先点一下 No. 列标题，排回帧号顺序。

SYN、ACK、PSH、FIN 各是什么意思 概念

它们是 TCP 头里的标志位。每个标志是一个开关，set = 1，表示这一帧带着这个意思。Info 方括号里写的就是打开了哪些开关。

标志意思打电话在哪出现
SYN我要建立连接“喂，听得到吗？”只在握手前两帧
ACK确认收到对方的东西“嗯，听到了”除第一帧外几乎每帧都有
PSH这帧带数据，马上交给程序正在说话GET、网页、图片
FIN我这边发完了，要关连接“我说完了”只在结束时
RST强制断开直接挂断异常时

ACK 到处都有，单看它认不出什么。有辨识度的是 SYN（开头）、FIN（结尾），以及不带 ACK 的 SYN（每条连接只有一个）。

ACK 标志和 Ack 数字是两回事。[ACK] 表示“这帧带了确认”；Ack=139 表示“前 138 个字节收到了，下一个要第 139 个”。例：146 的 GET 是 Seq=1、Len=138，Web 回的 147 就写 Ack=139。

怎么确认是握手，而不只是“头三个” 4.1

疑问：160–163 也是 [PSH, ACK]、[ACK]、[ACK]，凭什么前三个才算握手？

  1. 看 SYN。tcp.stream eq 1 && tcp.flags.syn == 1 只剩 2 行：143 [SYN] 和 144 [SYN, ACK]。
  2. 第三帧是紧跟在 [SYN, ACK] 后面、Apollo 发的 [ACK]：145，Seq=1 Ack=1 Len=0。
  3. 核对指纹：Seq=0 → Seq=0 Ack=1 → Seq=1 Ack=1；方向是 Apollo → Web → Apollo；三帧 Len 都是 0。
帧标志Seq / Ack / Len为什么不是握手
160[PSH, ACK]Seq=15497 Ack=463 Len=14480没有 SYN；大数；Len≠0，在传图片
161[ACK]Seq=463 Ack=29977 Len=0没有 SYN；只是确认收到了上面那段

答案：143,144,145

“all segments with the FIN flag set”为什么用 fin == 1 4.4

疑问：题目说 all segments，为什么不是所有帧，还要加 fin == 1？

  • segment：一个 TCP 包，就是列表里的一行。
  • with the FIN flag set：带 FIN 标志的。all 是说这种帧有几个就全写上。
  • set = 1。展开 TCP → Flags，能看到 Fin: Set（1）或 Fin: Not set（0），所以过滤器是 tcp.flags.fin == 1。

只写 tcp.flags.fin == 1 会出 8 个：110,111（SMTP）、232,233（Web）、391,392（External）、546,547（Intranet）。Task 4 只问 Web 这条连接，要和 stream 条件一起用。

tcp.stream eq 1 && tcp.flags.fin == 1

剩 2 行，两边各一个 [FIN, ACK]。答案：232,233。最后的 234 只有 [ACK]，不算。

数连接数为什么只数“喂”，不数“听到了” 4.5

“听到了”（SYN, ACK）和“喂”（SYN）属于同一通电话。两个都数，每条连接就被算了两次。

过滤器剩几行结果
tcp.flags.syn == 18每条算两次 ✗
tcp.flags.syn == 1 && tcp.flags.ack == 04每条只有一个开头 ✓

核对：Statistics → Conversations → TCP 标签页，一行是一条连接，也是 4 行。答案：4（SMTP、Web、External、Intranet）。
